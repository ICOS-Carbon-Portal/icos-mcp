## 2. mcpd in the gate, deployed as a shadow (`0fadfbb`, `e1361b5`)

* `run.sh` builds mcpd; `gate/mcpcheck.sh` replays it against a dedicated
  oracle checkout (`/root/rc/icos-mcp-oracle`, kept at the lock by

  A program variable named `bind` crashed it at start -- under Apple
  clang's LTO the runtime's call to `bind()` landed on the variable.
  Diagnosed with the m9 session from an A/B build; m9 0.27.1 prefixes
  module variables.

  had made every run on main fail since 11-07; recorded from the gate's
  own build.
* `mcpd.service` on :8094, 42 MB.  A real search answered the same data
  and byte-identical tool text as the Python server.

## 3. The Scala server (`mcp-scala/`)

Written to `cp-kernel`'s conventions (Scala 3.3.6, sbt 1.13, its
scalafmt/scalafix configs, the restricted style), with two departures the
README states, both for byte identity: the JDK's own HTTP server and
client instead of Pekko HTTP (which normalises a request's Content-Type
and writes `charset=UTF-8` where the oracle writes `utf-8`), and an
ordered JSON module instead of spray-json (whose objects are maps).  A
small Arrow reader and a Scala blosc decoder instead of large libraries.

The protocol, policy, validation and `list_datasets` first (41 rows),
then three agents in parallel worktrees -- the pages, search/describe/
stations, the selection tools -- merged without a conflict: **90 rows, the
2 declared, conformance identical**, 4,101 lines.  A test holds both float
printers to Python and pydantic over 20,000 values; it caught the one case
where Java's shortest `Double.toString` is not Python's (`4.9E-324` vs
`5e-324`).

CT122 got OpenJDK 21 and sbt; the gate builds and tests it and replays it
beside mcpd (PASS, 21 checks); `mcp-scala.service` on :8095, 98 MB, up in
2 s.  All three servers give byte-identical tool text for the hardest
describe.
